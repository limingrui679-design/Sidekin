# Full-resolution art archive

The main branch ships the complete 200-lineage catalog as 1,000 transparent 768×768 WebP runtime assets plus 200 lazy 320×320 thumbnails. This keeps a normal source clone and a packaged app practical without discarding the audited originals.

The full-resolution corpus is preserved at an immutable Git commit, with a convenience branch pointing to it:

- Commit: `0fca27df3ae9e4e32ab37651efb1a8f756912ffb`
- Convenience branch: `archive/full-png-corpus-v2.1`
- Repository: `limingrui679-design/Sidekin`

That archive contains the 1,000 accepted 1254×1254 transparent PNGs, full authoring sequences, repair candidates, visual audit sheets, expansion review sheets, and full-resolution README poster sources. `RuntimeAssets/manifest.json` records the source SHA-256 and runtime SHA-256 for every one of the 1,000 forms, so each lightweight asset remains traceable to its accepted source.

## Inspect without changing the main checkout

```bash
git fetch origin archive/full-png-corpus-v2.1
git worktree add ../Sidekin-full-art 0fca27df3ae9e4e32ab37651efb1a8f756912ffb
```

This creates a separate read-only-style working tree instead of mixing large source files back into the active source branch.

## Rebuild runtime assets

From the current main checkout, point the converter at the archived worktree:

```bash
SIDEKIN_SOURCE_CORPUS=../Sidekin-full-art/Sources/SidekinApp/Resources/Characters npm run assets:build
npm run assets:verify
```

The build is deterministic in dimensions, file naming, quality settings, provenance fields, and catalog coverage. WebP encoder implementations may change across future `sharp` versions, so a regenerated byte hash should be reviewed as an intentional asset update.

The archive is historical source evidence, not a consumer download or a second product release.
